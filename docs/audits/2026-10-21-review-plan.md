## 2. 优先修复的已确认问题

### A01：短仿真被误判为可以覆盖更长暗期

位置：src/main.tsx:492。

默认光伏＋LIC，办公室每周 5 天、每天 10 小时，最长暗期 62 小时：

| 仿真时长 | 模型暗期续航 | 页面判断能否覆盖 62 小时 |
| --- | --- | --- |
| 1 天 | null，含义为 24 小时内未耗尽 | 是，错误 |
| 3 天 | 31.640007 小时 | 否 |
| 30 天 | 31.640007 小时 | 否 |

原因是 `darkHours === null` 被直接当成可覆盖暗期。应比较已验证的下界与目标暗期；不足时显示“仿真时间不足以判断”，或独立模拟到完整暗期。PDF共用结论函数，也需要回归。

### A02：直接连接仍计入稳压器静态电流

位置：src/shared/engine.ts:212；检查 demand 及纯光伏对应路径。

本地隔离例子：3V 电池直接连接、其他条件不变，修改不应参与的稳压器 iq，从 0 改为 100µA，标称容量续航从约 17000 小时变为 1987.01 小时。两次均返回 conditional。例子只用于验证依赖关系，不是 Tiny 的实际电路。

修复应统一按实际存在的电源路径计算静态消耗、损耗和峰值，不靠 UI 隐藏字段规避。

### A03：保存与草稿恢复的身份信息不完整

位置：src/main.tsx:220、339、511；src/shared/draft.ts。

- 新方案及从大厅复制默认 public，员工也如此。已有公开提醒，但和设计文档中“员工个人默认私有”不一致，容易误公开。
- 恢复草稿会清空 current；草稿没有案例 ID、父修订、预期修订号、保存范围。刷新已有案例后可能变成新建保存，丢失继续编辑的关联。
- 已实现 guest localStorage / user sessionStorage 隔离，不建议为了跨设备恢复把公司私有草稿直接放进公共浏览器长期存储。

建议员工默认个人空间；公开作为明确动作；恢复完整关联并向服务端复核权限和修订，冲突时允许保留草稿、另存副本。

### A04：网页安全响应头尚未覆盖完整

本轮实测：首页缺 CSP、X-Frame-Options、X-Content-Type-Options、Referrer-Policy。API 正常响应有部分保护头，但匿名 admin 403 缺少这些头。配置仅 /api/* 先进入 Worker，不能以 API 中间件已有头推断 HTML 已受保护。

计划建立适合当前资源、打印及接口的 CSP、防第三方嵌入策略，并覆盖静态 HTML 与错误响应；验证不影响登录、打印和动态图表。未确认存在实际 XSS 或数据泄露。

### A05：有限流，但部分高成本路径保护不足

位置：worker/index.ts:175、346、532、565。

- 已有全局 21MiB 请求体上限，以及登录、案例保存、上传、PDF 解析、留言和 AI 的若干限流；不是“没有安全保护”。
- 普通 JSON 接口共享较大的上传上限；计算接口、创建元器件缺独立限流/资源额度。
- PDF 字节数有限制，但解析没有页数、展开文本量或工作量的事前预算；截取文本发生在整份提取之后。
- R2 上传成功而 D1 插入失败时，缺补偿清理；规格书去重先查询后插入，需数据库唯一约束兜底。

优先为路径设置不同体积/频次/并发/配额，给解析设置工作量上限，补上传一致性；用隔离环境检验，不能压测生产。

## 4. 性能和可维护性

现有优化应保留：AI 后台/图表延迟加载、展示用 WebP、演算输入缓存（24项）和无关文本不重算。不要重新把这些列为未实施。

本次 Home PC / Node 本地样本：

- 30 天混合方案，6 次：20.4、12.0、6.0、2.7、3.0、2.5ms。
- 365 天混合方案，6 次：32.4、32.2、32.4、37.0、32.5、35.8ms。
- 这不等于手机浏览器 INP。主线程内多个长仿真仍可能叠加阻塞，应测后决定 Web Worker、节流和中间结果复用。

建议：

1. 采集桌面/手机、冷/热缓存、长仿真及四方案比较的浏览器基线，区分网络、渲染、计算。
2. 哈希资源长期缓存；公共元件库使用版本/ETag，个人、公司数据维持私有或不缓存。
3. 列表分页：当前若干接口只取最近 100 条；元器件、案例修订和规格书列表存在全量加载。
4. 普通 API 增加超时、取消和请求序号，防止旧响应覆盖新选择；公共 busy 状态改成操作级。
5. 拆分约 2700 行 main.tsx 和大型 Worker 路由文件，按流程渐进提取，不做无收益的整站重写。
6. 加入 CI 运行类型、单元、隔离 D1 权限/并发、关键浏览器流程和资源预算；50 项单测不能替代登录/权限/计费的端到端验收。
7. 日志保留脱敏请求编号、阶段和真实终态；增加备份恢复演练、积压/错误/费用监控。现有 observability 已开启，无需描述成“完全没有日志”。

候选性能目标：真实条件下 p75 LCP≤2.5s、INP≤200ms、CLS≤0.1；第一批先建立可重复基线。未实测前不承诺达到。
