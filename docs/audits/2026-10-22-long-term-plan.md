# PowerMatch 后续研发路线（待讨论）

日期：2026-10-22（北京时间）。设备：Home PC / HomePC。项目：D:/Data/GitHub/PowerMatch，main。

本文件响应用户“列举后面可做的事情、制定长时间编程计划、声明 Agent 模型与推理强度”的要求。它是建议范围和验收方法，不是已交付功能，也不授权新的后台自动任务。本轮只收尾此前已授权的第二批发布，再整理计划；没有启动新的子 Agent 或下一批功能实现。

## 1. 当前基础与仍存在的缺口

第一批已修复短仿真误判、直接连接误计损耗、员工默认公开及草稿/身份/版本冲突；补了安全头、资源限额和依赖更新。第二批已实现结构化参数表单、部分七语补齐、安全比较副本、页面与修订链接、大厅分页、请求取消/竞态保护、哈希资源缓存和目录 ETag。应用提交为 cc94e3a、6eb9ea0，最终生产版本及验收以 HANDOFF.md 最新记录为准。

这些工作保留，不重复开发。尚未解决的主要问题：

- 性能：本机移动视口加 CPU 减速测试中，多图表流程仍有约 0.6–1.0 秒长任务；尚无真实手机或真实用户性能验收。完整目录仍一次读取，ETag 不减少数据库查询。
- 可追溯性：采用新 Spec 后，旧设计和报告的来源需要完整固化；AI 选型也应携带所采用的资料版本。
- AI 可靠性：供应商已消耗的 token 可能因后续 JSON/业务校验失败而漏记；在途任务和邮件发送需要中断恢复。
- 工程能力：当前仍是条件性模型，光源选择没有已校准的光谱计算；LIC 等若干默认项是标明假设的模板。MHO-C404 彩页没有完整功耗波形。
- 产品完整性：技术说明/错误/PDF 尚未全部七语；比较集合主要保存在本机；扫描 Spec 的 OCR、引脚级原理图和开源发布资料尚未完成。

## 2. 目标与优先级

用户目标保持不变：几乎不用填写参数，便能看懂不同供电方案能维持设备多久，并能调整、比较、保存和导出。

实现顺序建议为：可信资料与费用记录、流畅交互、完整设计工作流、真实数据支持的选型、工程交付。每批都应有用户能看到的成果，避免一次性重写全站。

按 **12–16 个可单独发布的小批次**规划，研发排期先以 **4–8 周**占位，前三批完成后按实际复杂度重估。它不是工期保证；原厂资料、硬件测量、真实账户验收和原理图复核可能延长日历时间。以下各阶段可以拆分，不要求等全部做完再上线。

## 3. 阶段与验收

### A. 流畅性与发布质量（优先，约 2 批）

1. 将长时间演算移入浏览器后台线程；快速连续改参数时，只接收最新一轮结果，显示“正在重新计算”。结果尚未对应当前参数时，保存/导出必须等待或明确保存哪份输入，不能把旧图表混入新报告。
2. 比较页按可见区域安排图表，复用相同输入的结果；保持计算精度，不以增大仿真步长掩盖卡顿。先分开测量计算与绘图耗时，再决定各项优化。
3. 给目录搜索、Spec、历史修订和论坛增加适合各自权限的分页；保留全库搜索能力，避免只搜索已加载的第一页。目录缓存失效随采纳/新增而更新，个人和公司内容不进入公共缓存。
4. 建立持续集成：类型、能量/单位、权限/并发、关键浏览器回归和构建资源大小；逐步拆分大型页面和路由文件，跟随功能改动进行。

验收：365 天演算和四方案比较中，输入、关闭和导航能及时响应；快速改 A→B 不会被 A 的迟到结果覆盖；保存/报告输入与结果匹配。桌面、390px 移动视口、键盘、200% 缩放、减少动画模式均覆盖。真实设备测试单独记录，实验室指标不冒充真实 INP。性能目标作为待测目标，不提前宣布达成。

### B. Spec 版本、上传与证据（优先，约 2 批）

1. Spec 修订不可变；参数保存原文来源、文件哈希、页码、单位、测试条件、来源类型及审核人。新文件和审核修正产生新修订，不直接改写已采用的历史证据。
2. 案例修订同时固化采用的 Spec、参数、光照/负载条件及引擎版本；手动选件、AI 选件和 PDF 使用同一份来源快照。旧方案可以复算或提示引擎版本差异，不能静默换参数。
3. 上传增加数据库唯一约束、重复提交幂等和 R2/D1 失败补偿；采用、替代、撤回、安全隔离分别记录。失败时不丢原稿、不留下无法管理的文件。
4. 建议把“社区公开但未采纳”与“安全隔离”分开：公开上传前明确可见性，安全扫描/处理完成前不提供匿名下载；不追溯性改变既有公开资料而不告知。正式实施前确认此产品边界。官方资料仍只有授权的秒秒测用户能采纳/维护。

验收：Spec v2 被采纳后，旧 case/PDF 仍指向 v1；两人同时审核不会互相覆盖；重复上传、对象已存但数据库失败、删除/撤回关联资料均有隔离回归。公开、公司、个人以及上传者、员工、唯一 admin 权限分别验证。

### C. AI 用量、费用与任务恢复（优先，约 2 批）

1. 在内容解析/业务校验前记录供应商返回的 usage；区分成功、供应商拒绝、格式失败、校验失败、用户停止等待、超时和用量未知。
2. 区分按量估算费用、套餐固定费用、示例摊销和账单对账。Token Plan 不再以少数健康检查外推“每次收费”；未获得实际用量/价格时显示未知。供应商账单才是实付对账依据。
3. 在现有原子次数额度之上增加并发上限、可配置预算及请求幂等。价格未知的模型采用次数/token 等额度，不假装金额上限能精确控制未知费用。
4. AI pending、邮件 sending 加租约与超时恢复；只有确定可安全重试的步骤才重试。供应商结果未知时先记录状态，不无条件重发导致重复扣费；邮件使用服务支持的幂等机制和明确通知偏好。
5. 健康检查区分“凭证连通”和“本应用需要的结构化能力”；前台显示可用状态、失败阶段及重试建议。价格导入逐家实现官方来源解析，显示支持范围、币种、单价单位及缓存/阶梯条件，不把任意链接当价格接口。
6. 后台增加积压、失败原因、费用来源及恢复操作。生产调度方案先检查 PowerMatch 的可用额度；不占用其他项目触发器，不自动购买套餐。

验收：HTTP 200 但 JSON 非法仍能记录已返回的 token；超时后状态可收敛，已知费用不丢、未知不填零；重复请求不重复创建业务任务；身份切换与额度并发正确。每家模型至少一次真实业务验收与模拟故障测试分开记载，不以健康检查代替建议质量验证。

### D. 完整设计与比较体验（约 2 批）

1. 把现有两种界面完整衔接：同一硬件下多设计方案、方案下不可变修订；比较集合可保存，按照原有个人/公司/公开规则共享。
2. 显示“哪些条件相同、哪些参数不同、差异导致什么结果”；共同条件锁定时明确覆盖范围；从任一快照继续设计始终保留原版。
3. 首页保留零输入演算，逐步引导换供电/器件。默认值、用户调整值、缺失值和资料不充分分别用颜色加文字/图标表示，不能只靠颜色。
4. 完成七种语言的技术说明、错误、后台及报告；浏览器/设备语言默认选择，手动选择优先并持久化。单位和数字统一，原厂资料保持原文，日期编辑固定 YYYY-MM-DD。
5. 可访问性与移动端：焦点、读屏标签、触控目标、字重对比、长名称折行；浮层的关闭/Escape/点击外侧与草稿保留继续作为发布门槛。

验收：大厅复制→换器件→查看依据→加入比较→继续编辑→保存特定修订→分享→重新打开，完整走通；陌生用户打不开公司/个人集合；七语和长文本布局没有关键内容丢失。

### E. 扫描资料、真实元件库与默认组合（约 2–3 批，部分依赖资料）

1. 支持文字 PDF、扫描 PDF、图片的候选提取，限制页数、图像尺寸、解压与提取文本量。表格字段附页码、原文片段、单位和测试条件，低可信字段逐项确认。文件中的文字始终是待分析资料，不是工具调用或权限指令。
2. 先补常用、可追溯的元件，避免追求条目数量：LR41、LR44、CR2032/2450/2477、AAA/AA，以及真实 LIC 1F、超容、可充电电池、LDO、采能 PMIC、不同材料 PV。每个厂家具体型号独立存储，不能用尺寸或化学体系代表同一放电曲线。
3. 每条资料标记“仅型号资料 / 可用于某些条件计算 / 在指定条件实测校核”，附缺失项和有效条件。原厂图片及 Spec 归属单独记录；公开开源不等于允许重新许可所有原厂 PDF。
4. 建立少量完整的推荐组合：低功耗 LCD、电子纸/BLE、纯电池、光伏直供、光伏加储能。资料不足时仍可用明确的假设模板，但不能称为已验证最佳电路。
5. 用选择目标替代唯一“最佳”：最小面积、最长无光时间、最低物料成本、最小体积。约束过滤后由计算引擎比较候选；AI 解释结果、提供取舍，不自行捏造电气参数。成本缺失时不宣称最便宜。

验收：选一个完整组合即能计算，点击参数可回到来源；在超出资料光照/温度/电流条件时提示外推；不支持的拓扑与一次性电池充电被拦截。推荐排序、锁定参数和单位转换可重现。

### F. 计算模型与实测校准（约 2–3 批，依赖原厂曲线和测量）

1. 光伏：按具体板材与光源的 I-V/功率测量数据计算；办公室/LED 等光源只有在有光谱或同条件数据时才应用修正。lux 与功率不能使用一个普适系数；板面已测照度不重复按角度扣减。
2. 电源：补冷启动与持续运行门限、MPPT 条件、效率随输入/负载变化、静态与反向漏电、欠压滞回、储能充放电及负载隔离。
3. 储能：电池容量随负载/温度/截止电压变化，自放电与老化、ESR/脉冲压降；LIC/超容有效电压区间、漏电、串联均衡与容差。没有曲线时保留近似模型的适用边界。
4. 负载：阶段表和 CSV 波形导入，区分设备输入端与电源端测量；显示刷新、BLE 广播和测量脉冲单独建模。事件/峰值分析与长期能量步进分别验证，不能用分钟平均值证明启动成功。
5. 结果给出可解释的敏感参数与条件范围，例如增加光伏面积/减少广播频率的效果；只有输入数据支持概率分布时才输出概率，避免伪造置信区间。

验收：保持能量守恒、单位和异常输入测试；有已知解/边界条件/阶跃与脉冲用例；与实测对照并记录误差和条件。Tiny 的周期计算值与“11µA 多”的经验记录分别保存；150lux 仅为原测试条件下记录。MHO-C404 要取得电子纸刷新、BLE、传感与休眠波形，产品彩页不能代替这些输入。

### G. 工程输出、运营与开源交付（分为约 2 批，可穿插）

1. PDF：基于不可变修订导出，带 ZenMeasure Logo、来源、引擎版本、假设、曲线及对比；七语字体、长表分页、图表和来源链接检查。先把现有浏览器打印做完整，再依据一致性需求决定是否增加服务端 PDF。
2. BOM 与原理图：先输出可追溯的器件清单，再用已核验的连接拓扑、符号、引脚及外围值生成 KiCad 文件；在支持的模板范围内做 ERC。能量示意图继续标为框图；通过 ERC 不等于硬件已验证或可直接量产。
3. 简单论坛：保留 case/修订/元件/应用的讨论关联，补分页、举报/管理、反灌水、通知偏好；100 次发言升级需排除删除/垃圾刷帖，避免鼓励无意义发言。
4. 运行维护：在现有日志上补请求编号、失败阶段、队列积压与费用观测；为 D1/R2 及加密密钥恢复制定最小访问流程，在隔离环境实际演练。备份里不夹带明文凭证，恢复验证不触碰生产数据。
5. 发布与开源：CI、隔离预发布配置、迁移演练/备份/回滚、开源许可证选择、贡献与安全反馈方式、自部署文档；代码、ZenMeasure 品牌、产品图和第三方 Spec 权利分开。许可证尚未授权，不擅自替用户决定。

验收：报告和 BOM 可追溯到同一设计修订；KiCad 可打开并列出 ERC 结论与限制；通知不会向错误身份或已退出订阅用户发送；备份可恢复到隔离环境；新贡献者可按文档启动，仓库/构建产物不含密钥。

## 4. 第一轮建议的连续工作包

先做三个可独立上线的包，而不是同时改动所有核心模块：

1. **性能包**：后台计算、过期结果隔离、比较图表调度、最小 CI；先消除测得的长任务，再扩展性能目标。
2. **AI 可靠性包**：失败用量保留、明确成本状态、任务超时恢复与幂等；不涉及修改用户现有 Key。
3. **证据包**：不可变 Spec 修订和设计来源快照、AI 选型引用一致性、旧方案/PDF 回归。数据库变更先在隔离 D1 演练。

性能与 AI 可以并行开发，但涉及共享数据模型、数据库或同一页面时先约定接口、串行集成。OCR、推荐优化和原理图排在来源版本固定之后。真实元器件资料收集可穿插，不用资料缺失阻塞无关的软件工作。

## 5. Agent 使用方案（拟定，未启动）

以下是开发 Agent 配置，与 PowerMatch 前台可选的 DeepSeek/Gemini/MiniMax 等业务模型无关。主 Agent 保持本次会话实际设置，不声称切换模型。最多三个子 Agent 同时工作，加主 Agent 共四个；验收角色通常替换已完成的实现角色。

| 角色 | 明确模型 | 推理强度 | 范围 |
| --- | --- | --- | --- |
| 前端与性能实现 | gpt-6.1-sol | high | 后台计算接入、比较/表单/语言、响应与可访问性；只改分配的前端文件 |
| 后端与 AI/资料实现 | gpt-6.1-sol | high | Spec/用量/任务状态、服务端权限和迁移草案；不自行发布或读写生产密钥 |
| 计算与安全独立复核 | gpt-6-astra | high | 能量/单位边界、版本可追溯性、权限/并发/费用；与实现者分开复核 |
| 回归验收，替换空出的实现槽位 | gpt-6.1-sol | medium；复杂权限/并发/计算回归升 high | 独立测试桌面/手机/身份/导出；明确模拟与真实验收区别 |
| 可选的只读资料整理，替换空槽 | gpt-6-luna | medium | 范围明确的资料目录与字段缺口；电气矛盾或关键结论升级独立复核 |

每次启动前显示角色、准确模型及强度，并把它们传入工具。模型不可用时报告实际替代设置，不默默冒充。只有主 Agent 集成、执行生产迁移和部署。任务按文件归属分工；不能用 Agent 数量替代审查，不能让实现者的自测成为唯一依据。

## 6. 发布与持续执行规则

- 每批完成：项目/目标核对 → 相关验证与独立复核 → 提交并推送 → 发布 Worker/前端 → 生产验收 → Git/Obsidian 交接。版本日期沿用现有自动生成方式。
- 验收范围覆盖能量/单位/非法输入、身份权限、token 消耗、草稿与修订、浮层关闭/焦点以及日期格式。只运行与变更和未解决风险相关的测试，不重复跑无价值的大套测试消耗配额。
- 在测试环境覆盖中断、并发、重复和迟到响应；生产只执行有界检查。真实登录、AI 调用、邮件送达、硬件实测分别留证，不从模拟结果推断。
- 遇到错误项目、guard 失败、不可恢复的数据风险或所需凭证缺失，停止相关生产步骤，继续可独立完成的工作；不宣称整个批次已经上线。
- 每批报告实际交付、剩余缺口与阻碍；未确认的计划不写入永久记忆。跨设备交接只同步本项目，不重置其他仓库的未提交内容。

## 7. 需要用户资料或产品取舍的地方

这些不阻塞首个性能包和多数可靠性实现，可在进入相关批次前一次性确认：

1. Tiny 的测量电压/温度/光源与供电结构；MHO-C404 功耗波形、储能型号、启动/掉电门限。二者现有彩页保留原样。
2. 常用 PV、LIC、PMIC 的具体型号与可公开资料；若资料不可公开，按公司范围管理，避免进入公开案例或 AI 外发上下文。
3. “最佳方案”首选目标建议为能覆盖目标暗期且资料充分，其次减小面积；成本和体积作为可切换目标。
