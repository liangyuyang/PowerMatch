## 1. 产品目标

让硬件工程师和产品经理回答：同一个设备，使用不同电源组合，在指定环境及工作策略下，第一次何时不能正常工作；怎样改变面积、储能或工作频率才能达到目标。

核心结论应同时覆盖：

- 连续运行：多久首次停机，原因是什么；再次来光后能否恢复、启动多久。
- 无光续航：从所选初始状态出发，可连续支撑多久。
- 周期收支：一周采能、消耗、损失、弃能与储能净变化。
- 瞬态能力：发送、采样、屏幕刷新、启动等峰值是否导致欠压。
- 反向设计：达到给定运行目标所需的最小光伏面积、可用储能、照明时间，或允许的最大发送频率。

“一周采能大于耗能”只是必要条件之一。储能不足、冷启动失败或峰值掉压仍可导致停机。仿真期内未停机，应显示“在所设 365 天内未中断”等有限结论，另说明老化模型覆盖范围，不输出无条件的“永久续航”。

## 2. 用户已明确的范围

- 七种界面语言：中文、英文、日文、韩文、西班牙文、法文、德文。
- Magic Link 登录；miaomiaoce.com、zenmeasure.com、zenmeasure.space 的秒秒测用户免费使用完整功能。
- 演算保存空间：公开大厅、秒秒测公司分享、个人。游客和外部用户的持久演算仅可公开保存。
- 设备可命名，保存并管理功耗输入；元器件可预置、手填或上传规格书辅助填写。
- 覆盖室内光伏、各类储能、可选电源管理；电池默认 CR2032，并能调整数量及串并联。
- 默认照明：每周 5 天、每天 10 小时、260 lux、垂直入射；角度可调。
- 前端与后端使用 Cloudflare。当前只做研究、系统设计和视觉设计。

## 4. UI 建议

主界面建议采用“输入—元器件关系—结论—时间变化”的结构。桌面优先，移动端按同一顺序纵向排列；比较在小屏上切换方案，避免缩小整张桌面。

### 元器件画布

- 灯具照向光伏，光伏电能流向 PMIC／供电路径，供电路径连接设备；可充电储能作为支路双向连接；一次电池作为单向备用支路。
- 节点支持点击更换型号、打开参数检查区；提供表单等价操作，不能依赖拖拽才能使用。
- 光流与电流使用不同线型。播放时间轴时，电能流方向、储能状态和设备开关同步变化；可暂停，支持减少动画偏好。
- 动画表达实际计算状态。断电时设备变灰；来光后可能先充电、满足冷启动门槛再开机。
- 串并联用简洁电池组图示及“2 串 1 并”等文字共同表达，同时展示组电压和容量。
- 第一版是受约束的系统拓扑编辑器；不要求用户画任意电路。

### 结果区

结论置顶：“预计首次停机……／仿真期内未停机／仅有光时可工作／电气条件不满足／资料不足”。下面按场景显示无光续航、一周能量平衡和峰值供电校验。

点击原因可定位到可操作输入，例如“储能不足以覆盖周末”，直接打开储能参数与反向求解；增加光伏面积可能改善补能速度，但储能上限未增加时不能当然解决最长黑暗时段。

输入不足时不显示虚构精确数值：只有平均电流可先做能量估算，峰值能力显示“尚未验证”。可比较明确参数范围下的保守／典型／乐观情景，但不把没有统计依据的上下界称为置信区间。

### 通用交互要求

- 所有数值带单位，支持 µA/mA、µW/mW、mAh/Wh、mF/F、mm²/cm² 的显式换算；单位不混入数据库数值。
- 日期编辑固定为 YYYY-MM-DD；显示语言和保存格式分离。定时光照按案例指定时区，初始默认北京时间。
- 弹窗与抽屉有明确关闭按钮，支持 Escape 与遮罩关闭；菜单支持 Escape 和点击外部关闭，尽量回焦触发控件。
- 关闭编辑浮层不丢弃未提交的草稿。删除先归档并提供撤销；被历史演算引用的设备／元件版本不被物理删除。
- 颜色之外同时使用文字、图标、线型说明状态；图表提供可读的数据表及键盘访问。
- 图像生成的三张概念稿是讨论用静态图。元器件外形、原理图、电压刻度、示例 36 小时等均不能用作工程验证。正式界面的部件形象与曲线由真实模型驱动。

## 5. 设备功耗输入

设备模型和供电方案独立：同一个设备可用于多个演算，修改设备应建立新版本，旧案例保持复现性。

| 输入层级 | 字段 |
| --- | --- |
| 快速估算 | 设备名称、供电电压、平均电流或平均功率、最低工作电压、预期工作天数 |
| 工作模式 | 睡眠、采样、无线广播／发送／接收、显示刷新、自定义模式；电流、持续时间、周期／每日次数 |
| 启动与峰值 | 上电电流与持续时间、峰值电流、最低电压、欠压重启策略、必要缓冲电容 |
| 进阶 | 多电压轨、工作日／周末策略、恒功率或恒电流负载、温度；后续导入功耗仪 CSV |

简单模式使用互斥工作状态，所有占空比须合理；完整活动电流替代该时段睡眠电流，不能重复计入。多个部件同时工作的模型显式标为可叠加，保留事件时间关系，避免只计算平均值而漏掉重叠峰值。

从电池容量和已有实测续航反推平均功耗可以作为辅助入口，但必须标为估算，记录使用的容量、截止电压与测试条件。

## 6. 供电模式与元器件输入

将原需求中的供电选择整理为三个清晰入口：

1. 单独电池／储能供电：默认 CR2032；也可选择充满的可充电电池或已知初始电压的电容。
2. 纯室内光伏：无续航储能；去耦电容可单独建模，不能暗中当成夜间电源。
3. 室内光伏＋储能／备用电池：EDLC、LIC、可充电电池、不可充电备用电池；PMIC／供电路径可选。

一次电池不进入充电路径。“光伏＋CR2032”是光伏优先和一次电池备用的混合供电。型号是否支持这条拓扑，需按 datasheet 和外部供电路径判断。

| 类型 | 关键输入 |
| --- | --- |
| 光伏 | 厂商型号、外形／有效面积及面积基准、数量、串并联、照度与光谱下的 Pmpp/Vmpp/Impp/Voc 曲线、温度与遮挡 |
| EDLC 超级电容 | 电容值、工作电压上限和截止值、初始电压、DC ESR、脉冲有效电容、漏电及测试条件、温度、老化 |
| LIC 锂离子电容 | 型号、容量／能量曲线、允许电压窗口、初始状态、ESR、漏电／自放电及条件；不能默认允许放电到 0V |
| 可充电电池 | 化学体系、标称电压、容量、OCV/SOC 或放电曲线、截止电压、初始 SOC、内阻、充放电电流、充电方式、效率、自放电、循环／日历老化 |
| 一次电池 | 型号、负载／温度／截止电压下的可用容量、放电曲线、内阻／脉冲能力、自放电；充电功能禁用 |
| PMIC／供电路径 | 冷启动电压与功率、启动后工作范围、MPPT、输入／输出效率图、静态电流、输出电压／电流、压差、UVLO 与恢复阈值、充电保护和备用电池切换 |

无 PMIC 时仍有直接供电的电气约束，不能把效率简单设成 100% 并认为任何组合都可工作。若直接连接光伏，工作点由光伏 I-V 与负载决定；没有 I-V 资料时只能做能量上限估算，不能等同于最大功率点供电。

### 串并联

默认 1S1P；提供串数 Ns、并数 Np 和总数量 Ns×Np，限定同型号同状态组合。电池的近似关系为 Vpack=Ns×Vcell，Qpack=Np×Qcell；电容 Cpack=Np×Ccell/Ns，Rpack=Ns×Rcell/Np，最终模型还计入连线、均衡与保护损耗。

串联不能简单相加 mAh；并联不提高电压。对一次电池并联、可充电电池多串、LIC 多串分别要求合适的隔离／保护／均衡描述；资料不足时保留数学估算，同时不标为电气兼容。

## 7. 光照日历与模型

用户指定：一周五天，每天十小时，260lux，垂直入射。建议日历初始值补充为周一到周五 09:00–19:00，休息日关灯，普通白光 LED 的明确参考光谱，温度 25°C；这些补充值都是可修改的产品建议。

这一时序每周照明 50h，无光 118h，周五 19:00 到周一 09:00 的最长无光段是 **62h**。界面需直接显示这一结果。仅有每日平均时长会丢失这个关键信息。

照度输入必须注明测量平面：

- 如果 260lux 是板面实际测量值，已包含该角度导致的照度变化，不能再次乘 cosθ。
- 如果是面向光源时的参考照度，简化单一方向模型可用 max(0, cosθ) 折减直射部分；θ 从板面法线计，0° 为垂直入射，60° 的直射分量约为一半。
- 多光源、漫反射和散射光保留单独分量，不能整体机械乘余弦。高级模型支持光源方向、散射比例或实际测量日程。

同 lux 不同光谱不等于同样可采功率。优先对指定光谱与型号的实测 Pmpp 曲线在支持区间内插值；260lux 不是所有产品共用一个 µW/cm² 数值。只有单点时可以做显式近似，并显示范围及证据不足；不可静默外推到未覆盖光照条件。

固定型号使用整片功率曲线与真实有效面积；“面积自由滑块”采用明确的单位面积模型，或提示这是定制面积估算，不能暗示固定型号可无代价任意裁剪且保持电压不变。

## 8. 演算引擎

采用确定性的、可独立运行的计算库。浏览器计算即时预览，服务端保存／分享前使用相同版本重新计算。AI 不参与物理数值求解，只辅助整理输入及解释结果。

统一内部单位为 SI，UI 负责显示换算。一般关系：

- 单轨平均负载：Pavg = Σ(Vi × Ii × di)，互斥状态占空比与背景耗电按定义处理。
- 电池名义能量 Vnom×Ah 仅为粗估；实际可用能量应由电压—容量曲线、负载、温度与截止条件求得。
- 理想定电容可用能量 E = ½C(Vhigh²−Vlow²)；J 转 Wh 除以 3600。LIC 非线性明显时对 C(V)×V 积分。
- 在储能边界定义充放电能量流：dE/dt = ηcharge×Pcharge − Pdischarge/ηdischarge − Pleak − Paux。负载先由当前采能路径供给，剩余才能充电；有缺口再放电或启动备用电池。每条损耗只计一次。
- 满电时多余能量记为弃能；到保护阈值触发停机／切换；不能只是把储能数值截到零后继续假装设备在运行。
- 短脉冲掉压的初步模型含 I×ESR 和 I×Δt/Ceff(Δt)。PMIC 输出能力、储能电压窗口和器件动态特性同时约束，不能用 DC 电容量保证毫秒脉冲。

多时间尺度：长期能量以光照及负载事件边界推进，峰值按短事件单独计算；每个长期步骤仍受瞬态校验约束。输入包含开始时刻、初始 SOC／电压、器件年龄与计算时长。区分“从满电开始”“从冷启动开始”和“达到周期稳定状态”的结果。

报告必须区分：首次停机时刻、累计正常时间、工作覆盖率、无光保持时间、恢复时间、一次电池消耗、净能量收支及限制因素。有限仿真不能证明无限寿命；长期预测受日历老化与数据适用期限制。

可复现保存内容：完整输入快照、组件版本、光照／负载日程、计算引擎版本、结果、证据状态及内容哈希。新算法／新元件库不能无声改写历史结果。

## 9. 三层空间与权限

| 能力 | 游客 | 外部邮箱登录 | 秒秒测有效成员 |
| --- | --- | --- | --- |
| 演算、手动输入、比较 | 可 | 可 | 可 |
| 阅读公开大厅 | 可 | 可 | 可 |
| 持久保存演算 | 仅公开大厅 | 仅公开大厅 | 默认个人，可发布到公司和／或大厅 |
| 查看公司分享 | 不可 | 不可 | 可 |
| 个人私密案例／设备库 | 无 | 无 | 可 |
| 修改／删除 | 自己匿名身份拥有的公开案例 | 自己的公开案例 | 自己的案例；分享不授予他人编辑原件 |
| 复制他人可见案例 | 复制后仅公开保存 | 复制后仅公开保存 | 复制到个人再选择分享 |

推荐将“所有权”和“发布范围”分开：内部用户始终拥有个人原稿，公司与大厅分别发布某个演算版本快照，可同时存在。更新原稿不自动公开新内容；有“发布更新”动作。读者默认只能查看、复制，复制记录来源。撤回分享不能回收他人已取得的副本，界面应在撤回时说明。

游客输入先为会话草稿；点击保存时按钮明确写“发布到公开大厅”，展示将公开的名称、参数和备注。服务器不提供游客可长期使用的隐形私人演算库。匿名作者以不公开的管理凭据／安全 Cookie 管理自己的公开案例，丢失凭据无法可靠证明原作者身份；鼓励邮箱登录保留管理权。页面上的 case ID 或分享 URL 不得拥有编辑权限。

外部登录解决跨设备作者身份问题，不带来公司／个人私密权限。公开作者显示昵称，默认不展示邮箱。

### Magic Link

- 服务端验证邮箱归属后，再解析并精确匹配 @ 后的完整域名：miaomiaoce.com、zenmeasure.com、zenmeasure.space；不使用子串匹配，不将恶意后缀或任意子域自动视为员工。
- 登录与授权分离；成员停用、会话撤销在下一次敏感请求生效。
- 推荐高熵单次短效 token，数据库只存 token 哈希，原子消费；会话 HttpOnly/Secure/SameSite Cookie。
- 链接 GET 展示继续登录页，由确认动作完成兑换，降低邮箱扫描器提前消费问题；配合请求节流、CSRF 和允许跳转地址校验。
- 所有案例、设备、元件、附件、导出、搜索和复制接口执行同一权限解析器。D1 不能依赖前端隐藏或套用其他数据库的 RLS 假设。
- 私密响应不进入公开缓存；权限变更应清理相应公开发布缓存。匿名凭据、Magic token、原始邮箱和 spec 原文不写入公开日志。

开源代码和计算功能的可用性，与官方托管站的保存政策分开。组织域名、空间规则应可配置，便于其他公司自部署，不能要求开源用户必须取得秒秒测邮箱。

## 10. spec 上传与自动填写

流程：选择元器件类型 → 上传 PDF／图片 → 文件检查与解析 → 候选参数 → 人工核对 → 应用到当前型号／创建新版本。

每个抽取字段保留：数值、单位、参数定义、测试条件、最小／典型／最大标记、页码／表格定位、来源文件及版本、机器／用户确认状态。OCR／模型置信程度只表示抽取证据，不等于电气适用性。

优先处理文字与表格；曲线读取需要坐标轴、单位、对数刻度与条件识别，作为后续可校对能力，不能声称上传任意规格书即可准确建模。容量 225mAh、0.225Ah、某负载下的实测容量不能混用；Absolute Maximum 不作为持续工作默认值。

模型只输出受 schema 约束的候选数据。上传文档视为数据，不能成为系统指令；超出单位／范围／物理关系的结果需要核对。用户手改字段不被重新识别无声覆盖。

原始 spec 默认私有。公开／公司分享默认包含用户确认的可复算参数和可公开来源链接；附带原始文件是单独动作。游客／外部用户的解析临时文件采用明确保留期，不能成为不受限制的私密文件库。公开器件目录的纳入需要资料来源及版本审核。

队列任务必须贯穿保存发起用户或匿名主体，区分发起人和执行 Worker，记录可归因的用量、失败和费用。公开服务的文件大小／页数／频率／并发限制属于运维边界；内部完整功能不等于无限计算资源。

## 13. 语言与首版节奏

先完整实现用户指定七语。建议同时提供繁体中文，并将巴西葡萄牙语列为下一优先级；随后根据真实访问、案例贡献与业务需求选择意大利语、越南语、泰语或印尼语。这是产品优先级建议，不是已验证的流量排名。

语言切换只翻译界面、说明和内置模板，不擅自改写用户的设备名称、案例备注、型号与原文 spec。翻译使用稳定术语表，数值本体与语言无关；德法文小数逗号等输入通过 locale 解析后规范化存储。长德文标签及日韩换行要纳入界面验收。

建议按以下顺序推进，仍待用户确定设计：

1. 明确主界面与核心字段；选择一个真实设备的耗电案例作为标定样例。
2. 确定性计算、三种供电入口、周历、EDLC／LIC／电池模型、基础串并联和真实预置元件。
3. 七语、Magic Link、三层案例、版本化保存、导出、组件参数核对。
4. 以真实 spec 验证自动填参；加入实测功耗 CSV、反向设计和更完整的老化／曲线模型。

用户要求的 spec 自动填参属于产品范围；上述顺序仅将其放在可靠手动计算之后，不能在缺少该功能时声称全部需求完成。

## 14. 验收方法

- 守恒与单位：μA/mA、mWh/Wh、mF/F、串并联变换，无采能时的已知解析解，满电弃能计数。
- 日程：默认周历应得到 50h 有光、118h 无光、最长 62h 黑暗；每周总光时相同但分布不同应产生不同续航结果。
- 失败路径：冷启动达不到功率、平均收支充足但周末不足、脉冲导致欠压、一次电池错误回充、LIC 低于允许窗口。
- 证据：数值保留典型／最大／最小及条件；网页与 PDF 冲突标识；缺少字段不可显示完整验证。
- 权限：匿名、外部、员工 A、员工 B、停用员工的读取／编辑／删除／复制／文件下载／搜索矩阵。
- 复现：同输入同版本在浏览器和 Worker 一致；历史案例不因库更新变化。
- 实物：用至少一个真实秒秒测设备和明确照明／储能条件比较实测与预测；此时才讨论模型误差范围。没有实测不得宣称真实设备续航已验收。
- UI：三种供电切换、保存范围、所有浮层关闭方式、焦点和草稿保留、七语、移动端均应实测。
